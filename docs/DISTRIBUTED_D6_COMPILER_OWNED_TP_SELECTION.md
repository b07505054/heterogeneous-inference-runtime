## 1. What D6 changed, precisely

The architecture audit (`DISTRIBUTED_COMPILER_ARCHITECTURE_AUDIT.md`)
found that `DistributedStrategyPlanningPass` computed real cost evidence
for both TP1 and TP2 but never compared it — selection was
`legal(TP2) && distributed.opt_in`, a boolean gate, not a profitability
comparison. Separately, D5's TP1/TP2 decision was made by a Python
regression (`tp_cost_model.py`) choosing between two already-compiled,
static `ExecutionPlan` files — not by the compiler.

D6 closes both gaps:

1. **A new, versioned profitability contract**
   (`distributed_profitability_contract_v1`, `DistributedPlanning.h`)
   defines real, consistent-unit inputs (model weight bytes, KV-cache
   bytes/token, workload shape, GPU memory) and outputs (predicted
   throughput in tokens/s, memory feasibility, rejection reasons).
2. **`estimateDistributedProfitability`** (`DistributedPlanning.cpp`) is a
   direct, numerically-verified C++ port of D5's Python regression.
3. **`DistributedStrategyPlanningPass`** now compares TP1 and TP2's
   predicted throughput and selects the higher one, subject to a hard
   memory-feasibility gate, with a deterministic epsilon tie-break.
   `distributed.opt_in` now only widens the candidate space considered
   — it no longer forces TP2.
4. **Calibration lives in a versioned target-profile JSON**
   (`nvidia_rtx4090_d6_distributed_profitability.json`), generated by a
   new offline script
   (`tools/generate_distributed_profitability_profile.py`) that reads
   real D5 calibration-split measurements only, never held-out rows, and
   cross-checks its refit against the published D5 result (confirmed
   `0.00e+00` difference).
5. **The Python `TPCostModel`** is explicitly reclassified (docstring
   update) as an offline calibration-fitting / oracle-reference utility.
   Five new tests prove no production code path imports or calls it.
6. **21 held-out workload cells were compiled fresh** — a real, separate
   `compile-for-target` invocation per cell — and every decision matched
   the real D5 oracle exactly.
7. **Real 2-GPU execution** was verified for both a compiler-selected TP1
   and TP2 plan on the same rented 2×RTX 4090 host used for D4B/D5.

## 2. The profitability contract

See `mlir_passes/include/serving/DistributedPlanning.h` for the full
declaration. Summary:

**Inputs** (all real, all pre-execution, all consistent-unit):
`DistributedModelProfile` (num_layers, hidden_size, num_attention_heads,
num_kv_heads — read from existing `llm.*` module attrs the frontend
already sets; weight_footprint_mb — supplied via `--model-profile`, since
it is deployment-time information, not a graph fact).
`DistributedWorkloadProfile` (input_tokens, output_tokens, concurrency,
max_model_len, max_num_seqs — supplied via `--workload-profile`, with a
conservative documented default when absent).
`DistributedProfitabilityCalibration` (contract_version, calibration
provenance hashes/commits, GPU memory budget, TP1/TP2 linear-regression
coefficient sets — read from the target profile's `distributedProfitability`
block).

**Candidate outputs** (`DistributedProfitabilityEstimate`, per TP degree):
`computed` (bool — false if inputs unavailable), `feasible` (bool — hard
memory gate), `predicted_throughput_tokens_per_s` (real unit, comparable
across TP degrees), `required_memory_mb`, `memory_budget_mb`,
`infeasibility_reason`, `truth_boundary`.

**Selection output** (module attrs, `distributed.selected_candidate_id`,
`distributed.selection_reason`, `distributed.policy_id` =
`"d6_profitability_selector_v1"`, `distributed.policy_truth_boundary`):
one of `tp2_excluded_opt_in_not_set`, `tp2_illegal_candidate_rejected`,
`no_distributed_capability`, `conservative_fallback_missing_or_invalid_calibration`,
`capacity_forced_tp1_infeasible`, `capacity_forced_tp2_infeasible`,
`tie_break_prefer_lower_tp_degree`,
`profitable_tp{1,2}_selected_predicted_throughput_higher`. Every candidate
(including an excluded/illegal one) still carries full legality + cost +
profitability evidence in `distributed.candidates[]` — nothing is dropped
silently.

**Units, explicitly**: throughput in tokens/second; weight/memory in
megabytes; KV-cache rate in kilobytes/token/GPU; all consistent, never
mixed with the older `DistributedCostEstimate.total_score`'s
undifferentiated byte+nanosecond+arbitrary-penalty sum (which remains,
unmodified, as D2's original single-operator evidence field — not used by
the D6 selector).

## 3. Calibration integration (Part D)

```
D5 calibration-split rows (17+8 cal. workloads × 2 models × 2 TP degrees)
  → tools/generate_distributed_profitability_profile.py
    (reuses heterogeneous-inference-runtime's own fit_linear_regression)
  → distributedProfitability block, embedded in
    configs/target_profiles/nvidia_rtx4090_d6_distributed_profitability.json
  → compile-for-target parses it into module attrs
  → DistributedStrategyPlanningPass reads it, never a raw benchmark file
```

- Cross-check: independently refit coefficients vs. the published
  `cost_model_fitted.json` — **0.00e+00 max difference**, both TP degrees.
- Held-out rows are never read by the calibration script (filtered by the
  same `split == "calibration"` label D5 declared before any measurement).
- Provenance: `calibrationDatasetHash` (sha256 of every calibration row's
  identity+throughput), `calibrationCompilerCommit`/`calibrationRuntimeCommit`
  (both repos' HEAD at generation time), `calibrationHardwareIdentity`
  (explicit 2×RTX 4090 PCIe-no-NVLink string).
- Fail-closed: `readCalibration()` (`DistributedStrategyPlanningPass.cpp`)
  sets `valid = false` unless `contract_version` matches
  `kDistributedProfitabilityContractVersion` exactly and every coefficient
  block is present — a missing or stale-version profile falls back to TP1
  with an explicit `conservative_fallback_missing_or_invalid_calibration`
  reason, never a crash, never a silent TP2.
- No `"0.5B => TP1, 7B => TP2"` literal exists anywhere — the compiler
  reaches that outcome by evaluating the real regression against each
  model's real weight/KV-cache features.

## 6. Comparison with the old Python runtime selector

Because `estimateDistributedProfitability` is a verified bit-for-bit port
of `tp_cost_model.py`'s regression (§D6.3 of the audit), the compiler's
21/21 decisions are **identical** to what D5's Python selector chose. This
is the expected, correct outcome of a faithful reimplementation — D6's
contribution is *where* the decision is made (inside the real compiler,
per-compilation, from calibrated coefficients) and *what* makes the
decision (a real, comparison-based selector, not an opt-in flag), not a
change in which answer is reached for these specific 21 cells.

## 7. Limitations (honest, not hidden)

- The linear regression can extrapolate to negative, physically
  nonsensical absolute predicted-throughput values outside the exact
  calibrated range (observed for 7B). The *ranking* between TP1/TP2
  remains correct in every tested cell; the absolute numbers are not
  independently meaningful. This is a cost-model-expressiveness
  limitation of a linear model fit on 2 model sizes, not a wiring defect.
- Calibration is specific to the exact 2×RTX 4090 PCIe host; nothing
  automatically fingerprints hardware and refuses a mismatched profile —
  only the honesty of the recorded `calibration_hardware_identity` string
  and human review.
- No cryptographic check ties an `ExecutionPlan` file to the specific
  compiler invocation that produced it (a pre-existing, unresolved trust
  boundary from the original audit).
- The tie-break path (`tie_break_prefer_lower_tp_degree`) is exercised
  only by a synthetic unit test — 0/21 real held-out cells produced a tie,
  as expected with real calibrated data.
- Only two points on the model-size axis (0.5B, 7B) were calibrated; the
  regression is not validated to interpolate correctly for sizes between
  them.

## 8. Reproduction commands

```bash
# Rebuild the compiler
cd ml-graph-compiler-runtime
cmake -S mlir_passes -B build-mlir \
  -DMLIR_DIR="$MLIR_DIR" -DLLVM_DIR="$LLVM_DIR" -DCMAKE_BUILD_TYPE=Release
cmake --build build-mlir -j"$(nproc)"

# Run the compiler test suite (31 tests, incl. DistributedProfitabilityTest
# and the updated DistributedStrategyPlanningPipelineTest)
cd build-mlir && ctest --output-on-failure

# Regenerate the calibration profile from real D5 data (optional --
# nvidia_rtx4090_d6_distributed_profitability.json already contains this
# output; cross-checks against the published D5 fit)
cd ..
<runtime-repo>/.venv/bin/python3 tools/generate_distributed_profitability_profile.py \
  --out /tmp/profile_block.json \
  --check-against <runtime-repo>/results/runtime_paths/distributed_d5_compiler_tp_policy/cost_model_fitted.json

# Fresh-compile any workload cell
./build-mlir/qwen-onnx-to-serving-mlir --graph-facts configs/models/qwen_7b_onnx_graph_facts.json --out /tmp/raw.mlir
./build-mlir/compile-for-target \
  --device-profile=configs/target_profiles/nvidia_rtx4090_d6_distributed_profitability.json \
  --model-profile=configs/models/qwen_7b_model_profile.json \
  --workload-profile=configs/workloads/qwen7b_in32_out32_c1.json \
  --mlir=/tmp/raw.mlir --out=/tmp/plan.json \
  --distributed-evidence-report=/tmp/evidence.json

# Runtime-side tests (heterogeneous-inference-runtime)
.venv/bin/python3 -m pytest tests/test_distributed_d6_compiler_owned_tp_selection.py -v

# Real 2-GPU launch of a fresh compiler-selected plan (requires the 2xGPU host)
.venv/bin/python3 scripts/run_d6_real_gpu_verification.py <plan.json> <label>
```
